# Data package — *What the Prompt Does Not Say: Prompt-Cued Access Control in AI-Generated Web Applications*

Complete replication package for a controlled factorial study of the security
posture of 75 web applications generated by five AI coding tools.

## The study in one paragraph

Five application specifications × five generation tools (Vercel v0, Lovable,
Bolt.new, Replit Agent, Claude) × three independent generations = 75
applications. Prompts were fixed verbatim and contained **no security
instructions**; when a tool asked a security question it was answered by
deferring to the tool's own default. Each application was analysed statically
for six exposure classes. The central result is that access-control exposure is
governed by whether the prompt named authentication, not by which tool
generated the application.

## Credentials and safety

No live credentials are present. The chatbot specification deliberately supplies
a **syntactically valid but non-functional placeholder** OpenAI key
(`sk-proj-AbCdEf…`), which appears in some applications' source and `.env`
files. The corpus was scanned before release for Supabase project URLs, JWTs,
and database connection strings: none were found. All applications were
generated and analysed by the author; no third-party application was scanned and
no deployed system was probed.
