# Photo Gallery

A public image gallery app where anyone can upload images and see them displayed in a masonry grid. No login required — just share the link.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080)
- `pnpm --filter @workspace/photo-gallery run dev` — run the frontend (port assigned by workflow)
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string
- Required env: `DEFAULT_OBJECT_STORAGE_BUCKET_ID`, `PRIVATE_OBJECT_DIR`, `PUBLIC_OBJECT_SEARCH_PATHS` — Replit object storage (auto-provisioned)

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- Frontend: React 19 + Vite + Tailwind CSS + Wouter (routing) + TanStack Query
- API: Express 5
- DB: PostgreSQL + Drizzle ORM
- File storage: Replit App Storage (GCS-backed presigned URL uploads)
- Validation: Zod, drizzle-zod
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)

## Where things live

- `lib/api-spec/openapi.yaml` — API contract (source of truth)
- `lib/db/src/schema/images.ts` — image metadata table
- `artifacts/api-server/src/routes/images.ts` — gallery CRUD routes
- `artifacts/api-server/src/routes/storage.ts` — presigned URL + object serving routes
- `artifacts/api-server/src/lib/objectStorage.ts` — GCS client wrapper
- `artifacts/photo-gallery/src/pages/gallery.tsx` — main gallery page
- `artifacts/photo-gallery/src/components/` — UploadZone, ImageLightbox, GalleryStats

## Architecture decisions

- Upload uses a two-step presigned URL flow: client requests a URL from the API, then PUTs the file directly to GCS. The API never receives the file bytes.
- Image metadata (objectPath, filename, contentType, sizeBytes) is stored in PostgreSQL after each successful upload.
- Images are served via `GET /api/storage/objects/:path` which streams from GCS.
- The upload endpoint is public (no auth) intentionally — this is a public communal gallery.
- `zod.int()` / `zod.url()` generated by Orval must be patched to `zod.number().int()` / `zod.string().url()` after each codegen run (Orval generates Zod v4 syntax; the lib imports plain zod v3-compat).

## Product

- Anyone with the link can view the gallery and upload images
- Masonry grid layout, batch uploads, drag-and-drop anywhere on the page
- Lightbox with full-screen view, filename/size info, and delete action
- Live stats (image count + total size) in the header

## Gotchas

- After running codegen, patch `lib/api-zod/src/generated/api.ts`: replace `zod.int()` → `zod.number().int()` and `zod.url()` → `zod.string().url()`
- Do not add auth to the storage upload URL endpoint — this gallery is intentionally public
- Root `package.json` has `pnpm.overrides` pinning react/react-dom to 19.1.0 to prevent Uppy v5 from pulling a duplicate React
